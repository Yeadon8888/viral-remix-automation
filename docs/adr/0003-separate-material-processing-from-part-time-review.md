# ADR-0003：分离豆包素材处理与兼职成片审核发布

## 状态

Accepted

## 背景

豆包素材页负责商品图转存、人脸检测、提示词生成和派发兼职任务。成片由另一套插件交给用户接单制作，本后台不负责接单或成片生产。

此前“成片回收并同步发布表”位于豆包素材页，并以豆包素材记录为选择单位。操作人员实际审核的是兼职表中的具体成片，同一素材也可能对应多条成片。两种职责和两种记录主键混在同一页面，容易造成选择数量不一致、重复操作含义不清以及发布失败原因难以定位。

## 决策

1. 豆包素材页只负责素材准备和同步兼职表，不再提供同步发布表入口。
2. 新增独立“兼职成片”页面，以兼职记录 ID 为选择和发布命令的主键。
3. 页面只读取外部插件已标记“已完成”且包含视频地址的记录，同时展示兼职审核标记和当前发布状态。
4. 当前阶段“审核通过”等同于“同步发布表”；暂不增加逐条审核状态机、接单或成片制作功能。
5. 同步作为单个后台批量任务执行，每批最多 200 条；前端明确显示已选数量、本次提交数量和剩余数量。
6. 后端在写发布表前重新校验：
   - 兼职任务已完成且视频地址有效；
   - 审核不是“无效链接”或“未去水印”；
   - 对应豆包素材仍满足 ADR-0002 的发布前置条件。
7. 以兼职记录 ID 为第一幂等键、视频地址为第二幂等键。已有发布记录只更新内容，不再次插入，也不覆盖原发布状态。
8. 所有发布任务共享发布资源锁，避免多个后台任务并发创建重复记录。

## 影响

### 正面

- 页面职责与真实操作对象一致：素材页处理素材，兼职页审核成片。
- 操作数量由兼职记录直接决定，不再由豆包素材与兼职成片的连接关系间接推算。
- 重复点击或历史记录重新同步不会二次插入发布表。
- 后台批量运行，关闭页面不会中断任务；失败记录会在运行记录中按兼职记录 ID 展示。
- 未来增加逐条审核时，可以在兼职页面扩展审核状态，不需要改动素材处理流程。

### 负面

- 兼职成片页面需要额外读取兼职表和发布表，首次刷新会产生两次飞书查询。
- 历史成片若对应源素材不再满足前置条件，会在发布时被拦截。

### 中性

- 外部插件仍负责接单和成片制作，本后台不会复制这套能力。
- 旧的豆包素材维度发布接口暂时保留用于兼容历史任务，但前端不再使用。

## 备选方案

- 继续在豆包素材页同步发布：拒绝，审核对象与选择对象不一致。
- 把接单、成片制作也搬入本后台：拒绝，与现有插件重复且超出当前产品范围。
- 同步时直接全部放行：拒绝，会让无效链接或源素材问题进入发布表。
- 同步请求内逐条串行完成：拒绝，页面等待时间长且浏览器中断风险高。

## 失败模式与恢复

- 同一批超过 200 条：只提交前 200 条，页面明确显示剩余数量，待本批完成后继续。
- 记录在页面读取后被删除或改为未完成：后台按失败记录返回，不创建发布记录。
- 飞书请求失败：后台任务保留失败明细，可对失败记录重新提交。
- 重复提交：命中兼职记录 ID 或视频地址后更新原发布记录。
- 新页面出现问题：可回滚应用版本；已存在的兼职表和发布表记录不需要迁移。
