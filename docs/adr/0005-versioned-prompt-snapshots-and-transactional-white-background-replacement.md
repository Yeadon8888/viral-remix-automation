# ADR-0005：版本化 Prompt 快照与事务式白底图替换

## 状态

Proposed

## 背景

批量豆包任务可能在排队期间遇到 Prompt 启用版本变更，付费白底图生成则可能在外部生成、下载、R2 上传或飞书回写任一阶段中断。如果任务运行时重新选择当前模板，或在 R2 上传前改写飞书链接，同一批次会产生不同语义，并可能丢失可用原图。

## 决策

1. Prompt 方案以稳定 `scheme_key` 识别；已启用或已被任务引用的配置版本内容不可变，变更内容必须创建新版本。
2. 批量任务在提交时固定 `country_code`、`template_scheme_key`、`template_record_id`、`template_version` 和 `execution_mode`；Worker 按指定记录执行，不再查询当前启用版本。
3. 每条豆包素材保存 Prompt 快照，下游兼职表与发布表继承国家、语言、方案和版本，发布时不再重新选择。
4. 白底图只在结果下载且验证为图片、上传现有 R2 成功后跨过白底图提交点；提交前不改写飞书的商品图存储链接。
5. 提交后用新链接使旧人脸检测失效并自动复检；复检仍含或疑似人脸时保持阻断。
6. Redis 检查点记录外部任务 ID、上传结果和提交阶段，恢复时不重复创建付费任务。
7. 飞书记录更新没有条件写能力；使用应用级记录锁和写前链接复查作为 best-effort 防并发措施，并通过字段权限避免任务期间人工改写商品图链接。

## 影响

结果可复现，且外部生成或 R2 失败不会破坏当前素材。代价是 Prompt 编辑流程需要“复制为新版本”，白底图恢复逻辑需要保留阶段检查点。
