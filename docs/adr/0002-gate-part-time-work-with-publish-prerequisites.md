# ADR-0002：以发布前置条件约束兼职任务派发

## 状态

Accepted

## 背景

豆包素材进入兼职任务后会消耗人工或视频生成资源。此前兼职入口检查了自有对象存储图片、人脸检测、最终提示词及目标国家/语言，但商品 ID 只在同步发布表时检查。因此存在任务已制作成片、最后才发现无法进入发布表的资源浪费，也存在前端与后端资格规则逐步漂移的风险。

视频地址、兼职任务完成状态和成片审核结果只有兼职任务完成后才会产生，不能在派发前检查。

## 决策

1. `DoubaoAssetService` 作为源素材发布前置条件的唯一判定入口。
2. 只有同时满足以下条件的素材才可进入兼职表：
   - 商品图已经转存到自有对象存储；
   - 当前存储图片已经完成检测且结论为无人脸；
   - 商品 ID 存在；
   - 最终视频生成提示词存在；
   - 提示词的目标国家和目标语言与本次派发选择一致。
3. 前端使用同一判定结果禁用不合格记录，并展示具体阻塞原因；后端在写兼职表前再次校验，防止绕过前端或缓存过期。
4. 同步发布表复用同一源素材前置判定，只额外检查兼职任务已完成、视频地址有效、审核结果不是“无效链接”或“未去水印”。
5. 发布阶段的复核只读取已有状态，不重新调用人脸检测、图片转存或提示词生成服务。
6. 历史兼职任务不自动删除；进入发布表时仍按新规则安全复核。

## 影响

### 正面

- 缺少商品 ID 等问题会在消耗兼职制作资源前被拦截。
- 兼职入口与发布入口共享同一源素材规则，降低规则漂移风险。
- 后端采用 fail-closed 校验，直接调用接口也不能绕过前置条件。
- 发布同步仍保持幂等，不重复创建已有发布记录。

### 负面

- 旧素材即使已有成片，如果后来不满足源素材前置条件，也会被发布复核拦截，需要先修复源记录。
- 前置规则变严后，可派发数量可能短期下降。

### 中性

- 标题、文案和标签当前不是发布表的硬性字段，暂不作为阻断条件；提示词生成仍会尽量生成这些内容。
- 成片链接和审核结果只能在兼职完成后检查，因此“可进入兼职表”表示源素材可发布，不保证最终成片一定审核通过。

## 备选方案

- 仅在发布阶段检查：拒绝，会在发现问题前消耗制作资源。
- 只在前端过滤：拒绝，可被旧页面、缓存或直接接口调用绕过。
- 在兼职表增加一套独立规则：拒绝，两套规则容易漂移。
- 派发前要求视频地址和成片审核：不可行，这些数据在派发时尚不存在。

## 失败模式与恢复

- 前端缓存过期：后端写兼职表前重新校验并拒绝不合格记录。
- 源素材在制作期间被修改：发布阶段轻量复核并阻断不一致记录。
- 飞书字段缺失：按不合格处理，并向页面和任务日志返回具体原因。
- 新规则异常：回滚应用版本；不删除已存在的兼职或发布记录。
