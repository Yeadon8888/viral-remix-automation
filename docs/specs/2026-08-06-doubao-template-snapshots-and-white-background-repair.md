# 豆包多模板、发布字段继承与白底图修复 Spec

## Problem Statement

豆包素材目前只能按国家/语言使用单一 Gemini 元模板，批量任务未固定方案与版本，兼职表和发布表也没有完整继承 Prompt 快照。这会让排队任务受到后续模板启停影响，并让发布阶段无法证明成片使用了哪个国家、语言和方案。

含人脸或疑似人脸的商品图目前以删除整条豆包素材为主要处理方式，造成其他已准备数据丢失。新流程需要通过付费图片生成服务修复为白底商品图，同时保证不重复扣费、不在上传失败时破坏原记录，且修复后仍经过人脸安全复检。

## Solution

豆包素材页在批量操作区统一选择目标国家/语言和 Prompt 方案。页面仅显示与当前国家、语言和选中素材品类兼容的启用方案。任务提交时固定稳定方案 Key、配置记录、版本和执行模式，且将 Prompt 快照写入每条素材。

`meta_generate` 方案继续调用 Gemini 生成最终提示词与发布内容；`direct_prompt` 方案只做确定性变量渲染，不调用 Gemini，标题写商品名，文案和标签保留已有值或留空。国家、语言、方案和版本自动继承到兼职表及发布表，发布页不再选择国家和语言。

人脸拦截记录通过单条或显式勾选批量操作发起白底图修复。外部客户端创建 `nano-banana-2` 异步任务并有限轮询，结果下载验证后上传现有 R2；只有跨过白底图提交点才替换商品图存储链接。替换使旧检测失效并立即复检，只有“无人脸”才恢复后续流程。

## User Stories

1. As an 豆包操作员, I want 在批量区统一选择国家/语言, so that 同批素材的市场语义一致。
2. As an 豆包操作员, I want 选择一个可用 Prompt 方案, so that 可针对不同转化策略生成内容。
3. As an 豆包操作员, I want 只看到当前国家、语言及品类可用方案, so that 不会误用不兼容模板。
4. As an 豆包操作员, I want 明确选择鞋类、服装或其他品类, so that 系统不依赖商品名称猜测。
5. As an 豆包操作员, I want 任务提交后保持选定版本, so that 配置启停不会改变排队结果。
6. As an 运营管理员, I want 线上现有模板作为 T1 默认, so that 旧请求保持兼容。
7. As an 运营管理员, I want 创建新版本而非改写已用版本, so that 历史结果可追溯。
8. As an 运营管理员, I want 同一方案维度只有一个启用版本, so that 新任务选择唯一。
9. As an 豆包操作员, I want `meta_generate` 方案使用 Gemini, so that 可生成完整标题、文案、标签和最终提示词。
10. As an 豆包操作员, I want `direct_prompt` 不调用 Gemini, so that 直接框架不被二次改写且不产生额外模型成本。
11. As an 豆包操作员, I want 直接方案保留已有文案和标签, so that 人工编辑不被清空。
12. As a 兼职成片操作员, I want 在兼职记录看到 Prompt 快照, so that 知道制作任务的市场与方案。
13. As a 发布审核员, I want 发布记录自动继承国家、语言、方案和版本, so that 不需要再次选择且不会与成片来源不一致。
14. As a 发布审核员, I want 保留马来西亚的具体语言, so that 马来语和英语不会被合并为国家值。
15. As an 豆包操作员, I want 将含/疑似人脸图片修复为白底图, so that 保留整条素材而非删除。
16. As an 豆包操作员, I want 单条发起白底图修复, so that 可处理一条拦截素材。
17. As an 豆包操作员, I want 显式勾选后批量修复, so that 不会因“按流程处理”意外产生付费任务。
18. As an 豆包操作员, I want 提交前看到数量和付费提醒, so that 成本可控。
19. As a system, I want 只处理当前检测链接等于存储链接的含/疑似人脸记录, so that 不基于过期检测修复新图。
20. As a system, I want 拒绝已被下游锁定的素材, so that 不会更换已派发任务的参考图。
21. As a system, I want 在外部生成或 R2 上传失败时保留原链接, so that 素材仍可恢复。
22. As a system, I want 替换后自动复检人脸, so that 只有安全新图进入后续流程。
23. As an 豆包操作员, I want 复检仍含人脸时看到阻断, so that 不会误以为修复已通过。
24. As a system, I want 检查点保留外部任务 ID, so that Worker 恢复时不重复扣费。
25. As an 豆包操作员, I want 停止批量任务并保留已完成检查点, so that 未开始项不再继续付费处理。
26. As an 运维人员, I want API Key 不出现在日志、响应、源码或命令参数, so that 凭证不被再次泄露。
27. As an 运维人员, I want 先轮换已泄露 Key 并通过 stdin 配置新 Key, so that 上线不使用失守凭证。

## Implementation Decisions

### Prompt 领域模型

- Prompt 配置字段：Prompt 名称、模板 Key、方案 Key、方案名称、执行模式、目标国家/地区、目标语言、适用品类、视频时长、版本、是否启用、模板内容、输出协议、变量说明和备注。
- 唯一性为 `scheme_key + region + language + category + version`；同一前四项只允许一个启用版本。
- 已启用或已被引用的版本不可原地改写内容，只能复制为新版本。停用不影响已排队任务。
- 第一期方案：`current_conversion`、`pain_physical_proof`、`multi_scene_proof` 为 `meta_generate`；`mx_shoes_10s` 为墨西哥+西班牙语+鞋类的 `direct_prompt`；`mx_clothing_10s` 为墨西哥+西班牙语+服装的 `direct_prompt`。
- 旧记录缺失方案 Key 映射 `current_conversion`，缺失执行模式映射 `meta_generate`；该兼容映射在读取层生效，生产迁移再显式回填。
- 商品品类为豆包素材显式单选：鞋类、服装、其他。未设置按“其他”读取，不得使用鞋服直接方案。

### 任务与执行器

- 单条和批量 Prompt 任务 payload 均必须包含 `country_code`、`template_scheme_key`、`template_record_id`、`template_version` 和 `execution_mode`；这些字段纳入去重摘要。
- 提交 API 在入队前验证配置记录存在、版本一致、已启用且与国家/语言/品类兼容。Worker 再次验证指定记录的身份与版本，但不要求其仍启用。
- `meta_generate` 调用 Gemini；`direct_prompt` 使用白名单变量的确定性渲染器，未知变量或缺失必需变量时整条失败。
- 方案执行成功后一次回写最终提示词、发布内容和 Prompt 快照。任意生成失败不写入部分新快照。

### 飞书字段迁移

| 表 | 新增/规范字段 | 类型 | 迁移规则 |
| --- | --- | --- | --- |
| Prompt 配置表 | `方案Key`、`方案名称`、`执行模式`、`目标语言`、`适用品类`、`视频时长`、`输出协议` | 文本/单选/多选/数字 | 现有豆包模板回填 T1 / `meta_generate`；先停用新版本导入，验证后启用 |
| 豆包素材表 | `商品品类`、`Prompt方案Key`、`Prompt方案名称`、`Prompt配置记录ID`、`Prompt执行模式`、`Prompt生成时间`、`白底图处理状态`、`白底图处理时间`、`白底图处理模型`、`白底图处理错误` | 单选/文本/日期 | 历史品类按其他读取；旧 Prompt 按 T1 / `meta_generate` 回填；不新增原图链接 |
| 兼职表 | `Prompt方案Key`、`Prompt方案`、`Prompt版本`、`Prompt执行模式` | 文本/单选 | 从豆包素材快照继承；保留现有目标国家和目标语言 |
| 发布表 | `目标国家`、`目标语言`、`Prompt方案Key`、`Prompt方案`、`Prompt版本`、`Prompt执行模式` | 文本/单选 | 从兼职记录快照继承；缺快照的历史成片从来源豆包素材回退读取，无来源 ID 则继续阻断 |

### UI 交互

- 豆包页批量区顺序为“国家与语言”、“Prompt 方案”、批量操作；方案选项显示名称、版本、执行模式、品类和时长，但提交使用稳定 Key 与记录 ID。
- 批量选中混合品类时，只显示所有选中素材都兼容的方案；若无交集则禁止提交并展示原因。
- 发布页删除国家/语言选择器，以只读方式展示每条兼职成片继承的快照。
- 人脸栏移除主要“删除记录”操作，增加单条“生成白底图”和批量“将勾选的人脸图片转为白底图”。
- 单条/批量提交前显示可处理数、被过滤数和付费确认；只有操作员显式勾选付费修复时，“按流程批量处理”才会发起白底图任务。
- “按流程批量处理”提供“需要人脸检测”选项；未勾选时在现有人脸状态字段记录“已跳过”，并允许提示词、兼职同步和发布继续。只有勾选检测后才可继续勾选付费的“自动白底图修复与复检”。更换商品图会使“已跳过”与普通检测结果一样失效。
- 旧删除 endpoint/action 保留一个版本并标记 deprecated，从当前 UI 移除；不自动删除 R2 对象。

### 白底图任务状态机

```text
待处理
  -> 生成中       (已创建或恢复外部 task_id)
  -> 上传中       (外部结果已下载并验证)
  -> 待复检       (R2 上传成功，单次回写新链接并使旧检测失效)
  -> 完成           (新链接复检为无人脸)

任一阶段 -> 失败   (保留阶段、可公开错误和检查点)
任一未提交阶段 -> 已停止 (用户取消；不删除已产生外部任务)
待复检 -> 失败        (复检失败，新链接保留但后续仍阻断)
待复检 -> 待处理   (复检仍含/疑似人脸；可由用户再次显式付费修复)
```

- 资格条件：当前状态为含人脸或疑似人脸，检测 URL 与当前存储链接一致，存储链接属于现有托管存储，且没有提示词、兼职记录 ID、已同步/冲突状态等下游锁。
- 为防止提交后并发覆盖，回写时再次比较期望原链接；不一致则记录冲突且不覆盖。
- 飞书更新记录接口不提供 revision/If-Match 条件写；因此应用级记录锁与写前复查可阻止本系统并发及已发生的外部修改，但不能宣称消除人工编辑恰落在最终 GET→PUT 窗口内的竞态。生产上应限制该字段人工写权限，并在迁移验收中明确此平台边界。
- 检查点至少保存：原链接摘要、外部 task ID、外部状态、结果 URL 摘要、R2 URL、当前阶段和最终结果。不保存 API Key。
- 结果下载必须限制响应大小、验证 HTTP 成功、内容类型和图片魔数；只允许 HTTP(S) 结果 URL。

### TokensFactory 集成

- 独立客户端封装 `POST /v1/videos` 和 `GET /v1/videos/{task_id}`；模型 `nano-banana-2`，参考图字段 `images`，画幅 `1:1`，分辨率 `2k`。
- 创建响应兼容 `id` / `task_id`；结果兼容 `image_url`、`url`、`metadata.result_urls[0]`。
- 轮询有总超时、有上限间隔和有限瞬时错误重试；明确的失败或取消立即终止。创建 POST 在未知是否成功时不盲目重发，依赖已持久化 task ID 恢复。
- 客户端及日志层对 Authorization、API Key、请求头和外部原始响应做脱敏；对前端只返回公开错误。
- 复用现有 R2 上传网关或 `R2Storage`，不新建存储实现。

### 生产迁移方案

1. 轮换已泄露 TokensFactory Key；不使用旧 Key，不在聊天或命令参数中传递新 Key。
2. 在飞书测试副本或测试表先新增字段；记录字段 ID/类型、默认值与可选值，验证应用读写。
3. 部署兼容读取版本：缺方案时读为 T1，缺执行模式时读为 `meta_generate`，白底图字段缺失时不影响原流程。
4. 在 Prompt 配置表创建停用的 T1/T2/T3 及墨西哥鞋服方案；比对输出协议、时长、出镜和场景冲突后才启用。
5. 在生产表新增字段，小批量回填历史 T1 / `meta_generate`，核对统计后扩大；不修改生产图片链接。
6. 部署写入 Prompt 快照和字段继承的版本，先对单条测试素材走通豆包→兼职→发布。
7. 使用模拟 TokensFactory 完成端到端验收，再通过 stdin 安全配置新 Key 和其他新环境变量；配置过程不回显值。
8. 先以单条、低并发开启白底图修复，核对外部账单、Redis 检查点、R2 结果、飞书链接和复检状态；再开启批量操作。
9. 保留旧删除 API 一个版本，监控是否有旧客户端调用；确认无调用后另票删除。
10. 回滚时先停止 Worker 领取新白底图任务，保留 Redis 检查点、R2 对象和新飞书字段，回滚应用；不删列、不回退已提交图片。

## Testing Decisions

- 优先测试外部业务行为：API 提交后 Worker 使用固定快照，并在飞书 fake 中产生预期字段；白底图从资格判定到 R2 提交和复检的整体行为。
- Prompt 配置服务测试维度唯一性、启用唯一性、不可变版本、旧数据兼容和国家/语言/品类过滤。
- 执行器测试两种模式：`meta_generate` 必须调用 Gemini；`direct_prompt` 明确断言 Gemini 未被调用，并测试变量错误。
- 字段继承沿用现有兼职幂等和发布同步测试风格，覆盖创建、更新、历史回退、马来西亚双语和缺来源 ID 阻断。
- TokensFactory 客户端使用伪 HTTP 传输测试响应兼容、超时、有限重试、失败/取消、脱敏和非图片下载拒绝。
- 白底图服务测试所有状态转移、下游锁、检测 URL 失配、R2 上传失败不写飞书、回写前链接冲突、复检拦截和成功。
- Redis 任务测试中断后使用已保存 task ID、已上传 R2 URL 或已提交结果恢复，并断言不再创建外部付费任务。
- UI 测试沿用现有 Node DOM stub，覆盖方案过滤、payload 快照、发布选择器移除、按钮资格、付费确认和主流程不隐式付费。
- 安全回归扫描响应、日志、任务 payload 和 Git diff，确认无 API Key；真实 Key 不进入测试。

## Out of Scope

- T4 低审核风险、无脸 UGC 方案。
- 通过 AI 自动推断商品品类。
- 逐行选择 Prompt 方案。
- 将白底图修复隐式加入“按流程批量处理”。
- 保存原图链接或新增原图归档字段。
- 删除旧 R2 对象、清空 bucket 或改变现有 7 天生命周期。
- 替换现有 R2/上传网关实现。
- 立即删除旧人脸记录删除 API。
- 部署、修改生产飞书字段、生产数据或环境变量。

## Further Notes

- 已暴露的 TokensFactory Key 视为已泄露，本 Spec 不使用、不复制、不落盘。实施到生产接入前，用户必须轮换并通过 stdin 安全配置新 Key。
- 简报中的墨西哥鞋类和服装原始模板位于已失效的微信临时路径，当前无法读取。导入票在实施前阻塞于用户重新提供权威文本；不得凭记忆重建。
- 菲律宾两份长 Prompt 存在 15 秒/多镜头、人物出镜与输出协议差异，不作为本期直接方案自动导入；T2/T3 内容导入时必须显式标注协议。
- 现有 `publish_sync` 与其测试中的未提交“缺来源记录 ID 提前阻断”修改属于用户工作，实施票必须在其基础上增量修改，不得覆盖。
