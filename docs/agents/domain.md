# Domain Docs

This repository uses a single-context domain documentation layout.

## Before exploring

- Read root `CONTEXT.md` when it exists.
- Read relevant decisions under `docs/adr/`.
- If either is absent, proceed silently; domain-modeling creates documentation lazily when decisions are resolved.

## Vocabulary and conflicts

- Use the glossary vocabulary from `CONTEXT.md` in specifications, tickets, tests, and code.
- Surface any conflict with an existing ADR explicitly instead of silently overriding it.
